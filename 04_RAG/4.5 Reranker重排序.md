## Reranker 是什么
Reranker（重排序器）负责对 Retriever 初步召回的候选文档重新计算相关性，并按照更精确的相关性分数重新排序。

它通常不在整个知识库上工作，而只处理 Retriever 找出的几十个候选 chunk，因此可以使用更复杂但更准确的模型。

```text
用户问题
	↓
Retriever：快速召回 Top-N
	↓
Reranker：精确重新打分
	↓
Top-K 高质量 chunks
	↓
LLM 生成答案
```

## 为什么需要重排序
向量检索和 BM25 的目标是快速缩小搜索范围，但初次排序不一定足够准确，常见原因包括：
1. 向量相似度只能近似表达语义相关性。
2. 一个 chunk 可能包含相关词，但并不能真正回答问题。
3. 多个候选 chunk 的相关性分数可能非常接近。
4. 混合检索得到的不同分数不一定处于同一尺度。

Reranker 会同时观察“查询 + 候选文本”，进行更细粒度的匹配，从而把真正有用的内容排到前面，减少传给 LLM 的噪声。

## Retriever 与 Reranker 的区别
| 对比项 | Retriever | Reranker |
| --- | --- | --- |
| 主要目标 | 快速扩大召回范围 | 精确排列候选结果 |
| 处理范围 | 整个知识库 | Retriever 返回的候选集 |
| 常用技术 | 向量检索、BM25、混合检索 | Cross-Encoder、ColBERT、LLM 打分 |
| 速度 | 快 | 相对较慢 |
| 精度 | 初步相关性 | 更细粒度的相关性 |

可以把 Retriever 理解为“初筛”，把 Reranker 理解为“复核和排序”。

## Reranker 的基本工作流程
1. 用户提出问题。
2. Retriever 召回 Top-N 候选，例如 20 或 50 个 chunk。
3. Reranker 对每个“问题-候选 chunk”配对重新打分。
4. 根据分数降序排列。
5. 选取前 K 个 chunk 交给 Context 构建模块。

一般有 $N>K$，例如先召回 50 个，再精排后保留 5 个。这样既减少漏召回，又控制最终上下文长度。

## Cross-Encoder 重排序
### 基本思想
Cross-Encoder 将查询和候选文本拼接后同时输入模型：

```text
[CLS] 用户问题 [SEP] 候选 chunk [SEP]
							  ↓
					  相关性分数
```

由于模型可以直接关注问题与文本之间的 token 级交互，所以通常比单纯的向量相似度更准确。

### 数学表示
设查询为 $q$，候选文档为 $d$，Cross-Encoder 输出相关性分数：

$$
s(q,d)=f_\theta([q;d])
$$

其中 $[q;d]$ 表示将查询和文档拼接，$f_\theta$ 表示经过训练的交叉编码模型。对候选集合 $D$ 排序：

$$
d_1,d_2,\dots,d_N=\operatorname{sort}_{d\in D}\big(s(q,d),\mathrm{descending}\big)
$$

### 优点
1. 查询和文档之间可以进行深层交互。
2. 对细节、否定关系和局部语义的判断通常更准确。
3. 适合对较小候选集做精排。

### 缺点
1. 每个 query-document 对都需要单独计算。
2. 候选数量过大时延迟和成本较高。
3. 不能像向量检索那样提前为文档一次性建立独立向量索引。

## Bi-Encoder 与 Cross-Encoder 的区别
Bi-Encoder 分别编码查询和文档：

$$
v_q=E(q),\quad v_d=E(d),\quad s(q,d)=\operatorname{sim}(v_q,v_d)
$$

文档向量可以提前计算并写入向量数据库，所以适合大规模快速召回。

Cross-Encoder 则把查询和文档一起输入：

$$
s(q,d)=f_\theta([q;d])
$$

它通常精度更高，但必须在查询发生后逐对计算。

| 模型 | 文档向量能否预计算 | 速度 | 精度 | 典型用途 |
| --- | --- | --- | --- | --- |
| Bi-Encoder | 可以 | 快 | 较高 | First-stage retrieval |
| Cross-Encoder | 不可以 | 较慢 | 通常更高 | Reranking |

## ColBERT：Late Interaction
ColBERT 是一种折中方案。它分别为 query 和 document 生成 token 级向量，不直接压缩成单个向量，再通过 MaxSim 等方式进行交互。

设查询 token 向量为 $q_i$，文档 token 向量为 $d_j$，一种典型打分形式是：

$$
s(q,d)=\sum_{i\in q}\max_{j\in d}\left(q_i\cdot d_j\right)
$$

与 Cross-Encoder 相比，ColBERT 的文档表示可以部分预计算；与普通 Bi-Encoder 相比，它保留了更细的 token 级匹配信息。

适用场景是希望在大规模检索中兼顾精度和效率的系统，但部署和索引复杂度也更高。

## 重排序的数学原理
Reranker 的核心是学习一个相关性函数 $s(q,d)$。训练数据通常包含：
1. 正样本 $d^+$：能够回答查询的文档。
2. 负样本 $d^-$：无关或不能回答查询的文档。

### Pairwise Loss
希望正样本分数高于负样本，可以使用：

$$
\mathcal{L}=\max\left(0, m-s(q,d^+)+s(q,d^-)\right)
$$

其中 $m$ 是间隔（margin）。

### Pointwise Loss
也可以把每个 query-document 对看成独立分类或回归样本：

$$
\mathcal{L}_{BCE}=-y\log\hat{y}-(1-y)\log(1-\hat{y})
$$

其中 $y$ 是相关性标签，$\hat{y}$ 是模型预测值。

### 排序结果
推理时只需要计算每个候选的分数并降序排列：

$$
\operatorname{rank}(d)=\operatorname{argsort}_{d\in D}\ s(q,d)
$$

## Python 实现 Cross-Encoder 重排序
下面示例假设 Retriever 已经返回一批候选 chunk：

```python
from sentence_transformers import CrossEncoder

query = "如何使用 Python 进行数据分析？"
candidates = [
	 "Python 常用于数据分析、机器学习和自动化。",
	 "向量数据库可以保存 embedding 并进行相似度检索。",
	 "Python 的 pandas 库常用于表格数据处理。",
	 "BM25 是一种基于关键词匹配的检索算法。"
]

model = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")
pairs = [[query, document] for document in candidates]
scores = model.predict(pairs)

ranked = sorted(
	 zip(scores, candidates),
	 key=lambda item: float(item[0]),
	 reverse=True,
)

for rank, (score, document) in enumerate(ranked, start=1):
	 print(f"{rank}. score={float(score):.4f} | {document}")
```

中文项目应选择支持中文或多语种的 reranker 模型，并根据模型说明调整输入格式，不能直接假设英文 MS MARCO 模型在中文数据上效果最佳。

## 如何选择 Top-K 和候选数量
设 Retriever 初步召回 $N$ 个，Reranker 最终保留 $K$ 个：

1. $N$ 太小：正确 chunk 可能还没进入候选集，Reranker 无法补救。
2. $N$ 太大：重排序成本和延迟增加。
3. $K$ 太小：上下文可能缺少回答所需信息。
4. $K$ 太大：LLM 输入变长，噪声增加，成本上升。

可以从 $N=20\sim50$、$K=3\sim8$ 开始，再通过离线评估调整，而不是直接凭经验固定。

## Python 代码实战：如何落地 Rerank
```python
from FlagEmbedding import FlagReranker

# 1. 初始化重排序模型（use_fp16=True 可加速推理）
reranker = FlagReranker('BAAI/bge-reranker-v2-m3', use_fp16=True)

# 2. 用户的查询
query = "为什么RAG系统需要重排序？"

# 3. 初步检索召回的候选文档（假设这是 BM25 或 Embedding 召回的 Top-4）
candidates = [
    "重排序是RAG架构中的精排阶段，用于提升检索结果的相关性。",
    "向量数据库是存储和检索高维向量的专用数据库系统。",
    "Rerank模型通过交叉注意力机制捕捉查询与文档的深层语义交互。",
    "大语言模型可以通过微调适应特定领域的任务需求。"
]

# 4. 计算 Query 与每个候选文档的相关性分数
# 模型会将 [query, doc] 拼接后进行交叉编码
scores = reranker.compute_score([[query, doc] for doc in candidates])

# 5. 按分数降序排列，获取精排后的结果
sorted_results = sorted(zip(candidates, scores), key=lambda x: x[1], reverse=True)

# 6. 打印精排结果
print("Rerank 精排结果：")
for rank, (doc, score) in enumerate(sorted_results, 1):
    print(f"[{rank}] 分数: {score:.4f} | {doc[:40]}...")
```

## 实践中的注意事项
1. Reranker 不能找回 Retriever 完全没有召回的文档，因此首先要保证召回率。
2. Reranker 使用的语言、领域和训练数据应尽量匹配业务场景。
3. 对同一文档的高度重复 chunk 应去重，避免 Top-K 被单一内容占满。
4. 可以结合 metadata 权限过滤，避免重排序把无权访问的内容排到前面。
5. 需要同时评估检索准确率、端到端答案质量、延迟和推理成本。
6. 对简单问答或小型知识库，直接使用 Retriever 可能已经足够，不必为所有场景增加 Reranker。

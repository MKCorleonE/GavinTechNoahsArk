## Retriever 是什么
Retriever（检索器）负责从知识库中找出与用户问题最相关的文档或 chunk，是 RAG 中连接“用户问题”和“LLM 上下文”的核心组件。

它的输入通常是用户查询，输出通常是按相关性排序的 Top-K 文档片段：

```text
用户问题
   ↓
查询处理
   ↓
Retriever
   ↓
Top-K chunks
   ↓
Context
```

Retriever 只负责找资料，不负责生成最终答案。答案生成由后续的 Generator（LLM）完成。

## 检索系统的基本流程
一个典型 Retriever 的在线流程如下：

1. 接收用户问题。
2. 对问题进行清洗、改写或扩展。
3. 使用一种或多种检索方法召回候选 chunk。
4. 按相关性排序并截取 Top-K。
5. 进行去重、过滤和上下文压缩。
6. 将结果交给 Reranker 或 Generator。

检索质量通常关注两个指标：
1. Recall（召回率）：正确答案所在的 chunk 是否被找回来。
2. Precision（精确率）：找回的 chunk 中有多少真正相关。

## Vector Search（向量检索）
### 什么是向量检索
向量检索先使用 embedding 模型将文档 chunk 和用户问题转换成向量，再在向量空间中查找最相似的 chunk。

```text
文档 chunk ──Embedding──> 文档向量 ──┐
									  ├─ 相似度检索 ──> Top-K
用户问题 ──Embedding──> 查询向量 ────┘
```

### 数学原理
设查询向量为 $q$，文档向量为 $d$，常见相似度包括：

余弦相似度：

$$
\mathrm{sim}(q,d)=\frac{q\cdot d}{\|q\|\|d\|}
$$

点积：

$$
\mathrm{score}(q,d)=q\cdot d
$$

欧氏距离：

$$
\mathrm{dist}(q,d)=\sqrt{\sum_i(q_i-d_i)^2}
$$

使用相似度时分数越大越相关；使用距离时距离越小越相关。

### 优点
1. 能理解同义词和语义相近但用词不同的表达。
2. 对自然语言问题较友好。
3. 适合查找“意思相近”的内容。

### 缺点
1. 可能忽略精确关键词、编号、产品型号和专有名词。
2. 效果依赖 embedding 模型质量。
3. 需要额外的向量生成和索引存储成本。

### Python 示例
```python
from sentence_transformers import SentenceTransformer
import numpy as np

documents = [
	"Python 常用于数据分析和机器学习。",
	"向量数据库支持高效的相似度检索。",
	"BM25 是一种经典的关键词检索算法。"
]

model = SentenceTransformer("sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2")
doc_vectors = model.encode(documents, normalize_embeddings=True)
query_vector = model.encode(["如何进行语义相似度搜索？"], normalize_embeddings=True)[0]

# 向量已归一化，点积等价于余弦相似度
scores = np.dot(doc_vectors, query_vector)
top_ids = np.argsort(scores)[::-1]

for index in top_ids[:2]:
	print(round(float(scores[index]), 4), documents[index])
```

## Keyword Search（关键词检索）
### 什么是关键词检索
关键词检索根据查询词是否出现在文档中，以及出现频率、文档长度等因素进行匹配。常见方法有倒排索引、TF-IDF 和 BM25。

关键词检索不需要把文本转换成稠密向量，搜索引擎可以通过倒排索引快速定位包含关键词的文档。

### TF-IDF（词频-逆文档频率）

#### 检索思想
TF-IDF 认为：如果一个词在当前文档里出现得越多，且在整个知识库的文档里越罕见，那么这个词对这篇文档就越重要。

它由两部分组成：
- TF (Term Frequency，词频)：这个词在当前文档中出现的次数。
- IDF (Inverse Document Frequency，逆文档频率)：这个词在整个知识库中出现的频率的倒数。

#### 数学公式与原理
假设知识库中共有 $N$ 篇文档，词项 $t$ 在文档 $d$ 中出现了 $f_{t,d}$ 次。

##### 1. TF：词频
TF（Term Frequency）描述词项在当前文档中的重要程度。最简单的词频定义是：

$$
\mathrm{TF}(t,d)=f_{t,d}
$$

为了减弱长文档和高频词的影响，实际中常使用归一化词频：

$$
\mathrm{TF}(t,d)=\frac{f_{t,d}}{\sum_{t'\in d}f_{t',d}}
$$

其中分母是文档 $d$ 中所有词项出现次数的总和。

也可以使用对数缩放，避免一个词重复很多次后权重无限增大：

$$
\mathrm{TF}_{\log}(t,d)=
\begin{cases}
1+\log f_{t,d}, & f_{t,d}>0\\
0, & f_{t,d}=0
\end{cases}
$$

##### 2. IDF：逆文档频率
IDF（Inverse Document Frequency）描述一个词在整个知识库中的稀有程度。

设 $\mathrm{df}(t)$ 表示包含词项 $t$ 的文档数量，则常见定义为：

$$
\mathrm{IDF}(t)=\log\frac{N}{\mathrm{df}(t)}
$$

如果某个词出现在很多文档中，它的区分能力较弱，IDF 就较小；如果只出现在少数文档中，它更能代表特定主题，IDF 就较大。

为了避免 $\mathrm{df}(t)=0$ 或数值过大，工程实现中常使用平滑版本：

$$
\mathrm{IDF}_{\mathrm{smooth}}(t)=\log\left(\frac{1+N}{1+\mathrm{df}(t)}\right)+1
$$

##### 3. TF-IDF：词项权重
TF-IDF 就是 TF 和 IDF 的乘积：

$$
\mathrm{TFIDF}(t,d)=\mathrm{TF}(t,d)\times\mathrm{IDF}(t)
$$

它体现了两个因素的平衡：
1. 词在当前文档中出现得越多，TF 越大。
2. 词在整个知识库中越少见，IDF 越大。
3. 一个词只有同时满足“在当前文档重要”和“在全局具有区分度”，TF-IDF 才会较高。

##### 4. 文档向量与查询向量
假设词汇表为 $V=(t_1,t_2,\dots,t_m)$，文档 $d$ 可以表示成一个 $m$ 维向量：

$$
\mathbf{v}_d=(\mathrm{TFIDF}(t_1,d),\mathrm{TFIDF}(t_2,d),\dots,\mathrm{TFIDF}(t_m,d))
$$

查询 $q$ 也可以用同样的词汇表表示为向量 $\mathbf{v}_q$。查询和文档之间通常使用余弦相似度：

$$
\mathrm{sim}(q,d)=\frac{\mathbf{v}_q\cdot\mathbf{v}_d}{\|\mathbf{v}_q\|\|\mathbf{v}_d\|}
$$

对所有文档计算相似度后，按分数从高到低排序，就可以得到关键词检索结果。

##### 5. 一个完整计算例子
假设知识库有 3 篇文档：

```text
D1：python data
D2：python machine learning
D3：java enterprise
```

对词项 `python`：
1. $N=3$。
2. `python` 出现在 D1、D2 中，所以 $\mathrm{df}(python)=2$。
3. 每篇包含 `python` 的文档中，它都出现 1 次。

使用未平滑公式：

$$
\mathrm{IDF}(python)=\log\frac{3}{2}
$$

因此：

$$
\mathrm{TFIDF}(python,D1)=1\times\log\frac{3}{2}
$$

对词项 `enterprise`：
1. $\mathrm{df}(enterprise)=1$。
2. 它只出现在 D3 中，因此：

$$
\mathrm{IDF}(enterprise)=\log\frac{3}{1}=\log 3
$$

因为 $\log 3>\log\frac{3}{2}$，所以 `enterprise` 的区分度高于 `python`。

这正是 TF-IDF 的核心原理：常见词的权重被压低，能区分文档主题的稀有词权重被提高。

##### 6. TF-IDF 的局限
TF-IDF 只根据词项及其统计频率工作：
1. “汽车”和“轿车”会被视为不同词，难以理解同义关系。
2. 查询词和文档词不一致时，可能无法召回语义相关内容。
3. 词汇表很大时，产生的向量维度很高，但通常是稀疏向量。

因此，TF-IDF 适合作为轻量、可解释的关键词检索基线，也常与稠密向量检索结合使用。


#### 致命缺点
TF-IDF 是个“老实人”。如果一个词在文档中出现 100 次，它的得分就是出现 10 次的 10 倍。这会导致某些恶意堆砌关键词的文档得分虚高，且长文档天然占优。

#### Python 示例
```python
from sklearn.feature_extraction.text import TfidfVectorizer

# 准备语料库（知识库）
corpus = [
    "广州早茶非常好吃，有虾饺和烧卖",
    "北京烤鸭是著名的传统美食",
    "广州不仅有早茶，还有丰富的夜宵文化"
]

# 初始化 TF-IDF 模型
vectorizer = TfidfVectorizer()
# 拟合并转换语料库（生成稀疏矩阵）
tfidf_matrix = vectorizer.fit_transform(corpus)

# 获取词汇表，看看哪些词被提取了
feature_names = vectorizer.get_feature_names_out()

# 计算查询与文档的相似度
query = "广州早茶"
query_vec = vectorizer.transform([query])

# 计算余弦相似度
from sklearn.metrics.pairwise import cosine_similarity
scores = cosine_similarity(query_vec, tfidf_matrix).flatten()

# 输出得分
for i, score in enumerate(scores):
    print(f"文档: {corpus[i]} | TF-IDF得分: {score:.4f}")
```

### BM25 的基本公式
BM25 对查询 $q$ 和文档 $D$ 的打分通常写为：

$$
\mathrm{score}(D,q)=\sum_{t\in q}\mathrm{IDF}(t)
\cdot
\frac{f(t,D)(k_1+1)}{f(t,D)+k_1\left(1-b+b\frac{|D|}{\mathrm{avgdl}}\right)}
$$

其中：
1. $f(t,D)$ 是词 $t$ 在文档 $D$ 中出现的次数。
2. $|D|$ 是文档长度，$\mathrm{avgdl}$ 是平均文档长度。
3. $k_1$ 控制词频饱和程度，$b$ 控制长度归一化程度。

### 优点
1. 对产品名、错误码、法规编号、API 名称等精确词汇很有效。
2. 不需要训练 embedding 模型，解释性强。
3. 对新词和专有名词通常更敏感。

### 缺点
1. 同义表达和词序变化可能无法匹配。
2. 查询词与文档词完全不同但语义相近时，召回能力较弱。
3. 中文需要先分词，或使用适合中文的 tokenizer。

### Python 示例
```python
from rank_bm25 import BM25Okapi

documents = [
	"Python 常用于数据分析和机器学习",
	"向量数据库支持相似度检索",
	"BM25 是经典的关键词检索算法"
]

tokenized_documents = [document.split() for document in documents]
retriever = BM25Okapi(tokenized_documents)

query = "关键词检索 BM25".split()
scores = retriever.get_scores(query)
top_ids = sorted(range(len(scores)), key=lambda i: scores[i], reverse=True)

for index in top_ids[:2]:
	print(round(float(scores[index]), 4), documents[index])
```

## Hybrid Search（混合检索）
### 什么是混合检索
Hybrid Search 同时使用向量检索和关键词检索，再融合两路结果。它结合了：
1. 向量检索的语义理解能力。
2. 关键词检索的精确匹配能力。

```text
用户问题
   ├──> Vector Search ──> 语义候选
   └──> Keyword Search ─> 关键词候选
				 ↓
			 结果融合
				 ↓
			   Top-K
```

### 线性加权融合
如果两种方法的分数已经归一化，可以使用：

$$
\mathrm{score}(d)=\alpha\,\mathrm{score}_{dense}(d)+(1-\alpha)\,\mathrm{score}_{sparse}(d)
$$

其中 $\alpha\in[0,1]$：
1. $\alpha$ 较大，更偏向语义检索。
2. $\alpha$ 较小，更偏向关键词检索。

### RRF 融合
当两路分数尺度不同，不建议直接相加，可以使用 Reciprocal Rank Fusion（RRF）：

$$
\mathrm{RRF}(d)=\sum_{m\in M}\frac{1}{k+\mathrm{rank}_m(d)}
$$

其中 $M$ 是检索方法集合，$k$ 是平滑常数，通常取60，$\mathrm{rank}_m(d)$ 是文档在方法 $m$ 中的排名。RRF 只依赖排名，不要求两路分数处于同一尺度。

### Python 示例：RRF 融合
```python
def reciprocal_rank_fusion(rank_lists, k=60):
	fused_scores = {}

	for rank_list in rank_lists:
		for rank, document_id in enumerate(rank_list, start=1):
			fused_scores[document_id] = fused_scores.get(document_id, 0.0)
			fused_scores[document_id] += 1.0 / (k + rank)

	return sorted(fused_scores, key=fused_scores.get, reverse=True)


vector_result = ["doc_2", "doc_1", "doc_4"]
keyword_result = ["doc_1", "doc_3", "doc_2"]

print(reciprocal_rank_fusion([vector_result, keyword_result]))
```

## 三种检索方式对比
| 方法 | 主要依据 | 擅长场景 | 主要问题 |
| --- | --- | --- | --- |
| Vector Search | 语义向量相似度 | 同义表达、自然语言问答 | 可能漏掉精确关键词 |
| Keyword Search | 词项匹配和词频 | 编号、代码、专有名词 | 难理解语义改写 |
| Hybrid Search | 两者融合 | 企业知识库、复杂问答 | 系统复杂度和调参成本更高 |

| 框架/工具 | 核心特点 | 适用场景 |
| :--- | :--- | :--- |
| LangChain / LlamaIndex | 生态最丰富，内置了 Dense、BM25、Hybrid、Re-ranking 等几乎所有检索器组件，开箱即用。 | 绝大多数 RAG 应用开发，快速搭建原型与生产系统。 |

## Retriever 的关键参数
### Top-K
表示召回多少个候选 chunk。K 太小可能漏掉答案，K 太大则会增加噪声和上下文长度。

### Score Threshold
表示最低相关性分数。低于阈值的结果可以被过滤，避免把明显无关内容交给 LLM。

### Metadata Filter
先按权限、部门、时间、文档类型等 metadata 过滤，再进行相似度检索，可以提升准确性和安全性。

### Query Rewrite
将口语问题改写为更适合检索的查询。例如把“这个东西怎么弄”改写为“系统 A 的安装步骤和依赖要求”。

### Reranker
Retriever 通常负责快速召回，Reranker 再用更精细的模型重新排序。两阶段结构可以兼顾速度和准确率。

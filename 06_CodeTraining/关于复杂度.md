# 时间复杂度与空间复杂度

复杂度分析用于估算：当输入规模变大时，算法的运行时间和额外内存会如何增长。
它关注的是增长趋势，而不是某台机器上的实际运行毫秒数。做 coding 题时，复杂度通常是判断解法能否通过的第一道门槛。

## 1. 基本记号

- `n`：输入数据的规模，例如数组长度、字符串长度、节点数。
- `m`：第二个输入的规模，例如两个数组长度分别为 `n` 和 `m`。
- `V`、`E`：图的顶点数和边数。
- `k`：结果数量、窗口大小或数字位数等其他规模参数。
- `O(f(n))`：渐进上界，刷题中通常用它描述最坏情况下的增长速度。
- `Theta(f(n))`：渐进紧确界，表示增长速度就是这个量级。
- `Omega(f(n))`：渐进下界。

例如，`O(n)` 不代表一定执行 `n` 次，也不代表一定比 `O(n log n)` 快很多；它表达的是输入变大时，两者的增长阶不同。

## 2. 复杂度分析的核心规则

### 2.1 忽略常数和低阶项

```python
for _ in range(3 * n + 10):
	pass
```

循环次数是 `3n + 10`，复杂度写作 `O(n)`。复杂度分析只保留最高阶项，并忽略常数：

```text
O(5n + 20)       -> O(n)
O(n^2 + n)        -> O(n^2)
O(2^n + n^3)      -> O(2^n)
```

### 2.2 顺序执行取较大项

```python
for x in nums:          # O(n)
	pass
for x in nums:          # O(n)
	for y in nums:      # O(n^2)
		pass
```

总复杂度是 `O(n + n^2 + n) = O(n^2)`，不是 `O(2n^2)`。

### 2.3 嵌套循环通常相乘

```python
for i in range(n):
	for j in range(n):
		pass
```

外层执行 `n` 次，内层每次执行 `n` 次，总复杂度为 `O(n^2)`。

如果内层规模随外层变化，则要写求和。例如：

```python
for i in range(n):
	for j in range(i):
		pass
```

执行次数为 `0 + 1 + ... + (n - 1) = n(n - 1) / 2`，仍然是 `O(n^2)`。

### 2.4 每次减半通常是对数复杂度

```python
while left <= right:
	mid = (left + right) // 2
	# 每轮排除约一半区间
```

规模从 `n` 变为 `n / 2`，再变为 `n / 4`，直到 `1`，需要约 `log_2 n` 轮，因此是 `O(log n)`。
对数的底数在大 O 中可以忽略，所以 `log_2 n`、`log_10 n` 都写作 `O(log n)`。

### 2.5 不同输入规模不要强行合并

两个数组分别排序时，复杂度应写成 `O(n log n + m log m)`；只有明确 `m = n` 时，才可以简写为 `O(n log n)`。

### 2.6 分支取最坏情况

```python
if condition:
	do_linear_work()       # O(n)
else:
	do_quadratic_work()    # O(n^2)
```

最坏时间复杂度是 `O(n^2)`。如果题目要求平均复杂度或均摊复杂度，则需要单独说明分析口径。

## 3. 常见复杂度等级

从通常更理想到通常更危险：

| 复杂度 | 常见例子 | 直观含义 |
| --- | --- | --- |
| `O(1)` | 数组按下标访问、哈希表平均查找 | 与输入规模无关 |
| `O(log n)` | 二分查找、堆操作 | 每次缩小一部分规模 |
| `O(n)` | 遍历数组、哈希表遍历 | 扫描一次输入 |
| `O(n log n)` | 归并排序、堆排序、快速排序平均情况 | 分治并做线性合并 |
| `O(n^2)` | 冒泡排序、选择排序、枚举所有数对 | 两层独立枚举 |
| `O(n^3)` | 三层枚举、Floyd | 三个维度组合 |
| `O(2^n)` | 子集枚举、未优化的递归选/不选 | 每个元素产生两种选择 |
| `O(n!)` | 全排列枚举、暴力旅行商 | 枚举所有排列 |

`O(2^n)` 和 `O(n!)` 通常只适合较小的 `n`。看到 `n` 达到几千或几十万时，通常应优先考虑 `O(n)` 或 `O(n log n)`；最终仍要结合题目时限、语言和常数判断。

## 4. 时间复杂度和空间复杂度

### 4.1 时间复杂度

统计基本操作随输入规模增长的次数。一次赋值、比较、哈希查找等通常视为 `O(1)`，但它们在循环中重复执行后要累加。

### 4.2 空间复杂度

统计算法运行期间随输入规模增长的额外空间。通常分为：

- **输入空间**：题目已经给出的数组、字符串、图等。很多题目不把它算入额外空间。
- **辅助空间**：算法新申请的数组、哈希表、队列、递归调用栈等。
- **输出空间**：返回结果本身占用的空间。需要看题目或讨论约定是否计入。

例如：

```python
def find_max(nums):
	answer = nums[0]
	for value in nums:
		answer = max(answer, value)
	return answer
```

只使用固定数量的变量，时间复杂度为 `O(n)`，额外空间复杂度为 `O(1)`。

```python
def copy_values(nums):
	result = []
	for value in nums:
		result.append(value)
	return result
```

需要新数组保存 `n` 个元素，因此时间复杂度为 `O(n)`，额外空间复杂度为 `O(n)`。若把返回数组算入输出空间，则总空间也为 `O(n)`。

### 4.3 递归空间

递归的空间复杂度主要看**同时存在的调用栈深度**，不是所有递归调用次数的总和。

- 链式递归深度为 `n`：空间 `O(n)`。
- 二分递归每次减半：栈深度 `O(log n)`。
- 深度优先搜索在链状树上：栈空间 `O(n)`。
- 如果递归过程中保存了 `n` 个状态，还要把这些状态空间一起计算。

递归函数即使每层只使用 `O(1)` 局部变量，调用深度为 `n` 时也不是 `O(1)` 空间。

## 5. 常规数据结构操作复杂度

下表默认讨论常见实现和平均情况；哈希表最坏情况可能退化为 `O(n)`。

### 5.1 数组与字符串

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 按下标读取/修改 | `O(1)` | 连续内存可直接定位 |
| 尾部追加/删除 | `O(1)` 均摊 | 动态数组扩容时单次可能为 `O(n)` |
| 头部或中间插入/删除 | `O(n)` | 后续元素需要移动 |
| 查找某个值 | `O(n)` | 无序数组需要遍历 |
| 有序数组二分查找 | `O(log n)` | 前提是有序且支持随机访问 |
| 反转 | `O(n)` | 原地反转额外空间可为 `O(1)` |
| 拼接两个字符串 | 通常 `O(n + m)` | 与结果长度有关 |

Python 中 `list` 是动态数组，不是链表；`list.pop(0)` 和 `list.insert(0, x)` 都是 `O(n)`。需要频繁从两端操作时，应考虑 `collections.deque`。

### 5.2 链表、栈和队列

| 结构与操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 链表访问第 `i` 个节点 | `O(n)` | 必须从头移动 |
| 已知节点位置的链表插入/删除 | `O(1)` | 不包含寻找该节点的时间 |
| 栈 `push` / `pop` | `O(1)` | 后进先出 |
| 队列两端操作 | `O(1)` | 应使用双端队列 |
| 优先队列插入/弹出 | `O(log n)` | 通常由堆实现 |

### 5.3 哈希表与集合

| 操作 | 平均时间复杂度 | 最坏时间复杂度 |
| --- | --- | --- |
| 插入、删除、查找 | `O(1)` | `O(n)` |
| 遍历所有元素 | `O(n)` | `O(n)` |

哈希表适合解决“是否出现过”“计数”“按照键快速查找”等问题，但元素必须可哈希，且不能依赖遍历顺序来获得排序结果。

### 5.4 二叉搜索树、堆和并查集

| 结构与操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 平衡二叉搜索树查找/插入/删除 | `O(log n)` | 高度为 `O(log n)` |
| 退化二叉搜索树查找/插入/删除 | `O(n)` | 可能退化成链表 |
| 堆取最小/最大值 | `O(1)` | 只保证堆顶 |
| 堆插入或弹出堆顶 | `O(log n)` | 向上或向下调整 |
| 建堆 | `O(n)` | 自底向上建堆，不是 `O(n log n)` |
| 并查集 `find` / `union` | 近似 `O(1)` | 路径压缩 + 按秩/大小合并，严格写法为 `O(alpha(n))` |

## 6. 常见算法复杂度

### 6.1 查找与排序

| 算法 | 最好 | 平均 | 最坏 | 额外空间 |
| --- | --- | --- | --- | --- |
| 线性查找 | `O(1)` | `O(n)` | `O(n)` | `O(1)` |
| 二分查找 | `O(1)` | `O(log n)` | `O(log n)` | 迭代 `O(1)` |
| 冒泡排序 | `O(n)`* | `O(n^2)` | `O(n^2)` | `O(1)` |
| 选择排序 | `O(n^2)` | `O(n^2)` | `O(n^2)` | `O(1)` |
| 插入排序 | `O(n)` | `O(n^2)` | `O(n^2)` | `O(1)` |
| 归并排序 | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(n)` |
| 快速排序 | `O(n log n)` | `O(n log n)` | `O(n^2)` | 平均 `O(log n)` |
| 堆排序 | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(1)` |

`*` 冒泡排序只有在实现了“本轮没有交换则提前结束”时，最好情况才是 `O(n)`。
排序复杂度还要注意：原地排序的额外空间和稳定性可能影响选型，不能只看时间复杂度。

### 6.2 树和图

设图有 `V` 个顶点、`E` 条边，使用邻接表存储。

| 算法 | 时间复杂度 | 常见空间复杂度 |
| --- | --- | --- |
| 二叉树 DFS/BFS | `O(n)` | `O(n)` |
| 图 DFS/BFS | `O(V + E)` | `O(V)`，不含输入图 |
| 拓扑排序 | `O(V + E)` | `O(V)` |
| Dijkstra + 二叉堆 | `O((V + E) log V)` | `O(V + E)` |
| Bellman-Ford | `O(VE)` | `O(V)` |
| Floyd-Warshall | `O(V^3)` | `O(V^2)` |
| Kruskal | `O(E log E)` | 取决于排序和并查集 |
| Prim + 二叉堆 | `O((V + E) log V)` | `O(V + E)` |

图算法中不要只写 `O(n)`：边数可能远大于顶点数，必须区分 `V` 和 `E`。

### 6.3 典型搜索与动态规划

| 方法 | 常见复杂度 | 关键影响因素 |
| --- | --- | --- |
| 回溯 | `O(分支数^深度)` | 是否剪枝、是否去重 |
| 子集枚举 | `O(2^n)` | 每个元素选或不选 |
| 全排列 | `O(n!)` | 可能还要乘上复制结果的 `O(n)` |
| 记忆化递归 | `O(状态数 * 每状态转移)` | 每个状态只计算一次 |
| 一维动态规划 | 常见 `O(n)` 或 `O(nk)` | 状态数量与转移数量 |
| 二维动态规划 | 常见 `O(nm)` | 网格或两个字符串的状态 |
| 单调栈 | `O(n)` | 每个元素最多入栈、出栈一次 |
| 滑动窗口/双指针 | 通常 `O(n)` | 左右指针总体各移动不超过 `n` 次 |

动态规划的空间不一定等于状态表大小。例如滚动数组只保留上一行时，可以把 `O(nm)` 空间优化到 `O(m)`；但要确认状态转移不会读取已经被覆盖的数据。

## 7. 容易误判的情况

### 7.1 两个指针不一定是 `O(n^2)`

```python
left = 0
for right in range(n):
	while left < right and invalid():
		left += 1
```

虽然代码有一个 `for` 和一个 `while`，但 `left` 在整个过程中最多增加 `n` 次，`right` 也只增加 `n` 次，所以总时间是 `O(n)`，不是 `O(n^2)`。

### 7.2 排序后再扫描通常是 `O(n log n)`

排序 `O(n log n)`，扫描 `O(n)`，相加后仍为 `O(n log n)`。

### 7.3 切片、拼接和复制不是 `O(1)`

```python
part = nums[left:right]
```

通常会复制 `k = right - left` 个元素，时间和额外空间都是 `O(k)`。递归中反复切片可能让本来线性的算法变成平方级别。

### 7.4 输出结果会影响复杂度

如果题目要求返回所有满足条件的组合，结果本身可能有指数级数量。此时即使搜索过程很快，也至少要付出保存或生成结果的成本，通常称为输出规模（output-sensitive）复杂度。

### 7.5 均摊复杂度不等于每次都快

动态数组扩容时，一次追加可能需要复制所有元素，单次为 `O(n)`；但大量追加的总成本平均到每次后，追加操作是 `O(1)` 均摊复杂度。

## 8. 做题时的分析步骤

1. 明确输入规模：是一个 `n`，还是 `n`、`m`、`V`、`E` 等多个规模。
2. 找出最耗时的操作：遍历、排序、哈希操作、堆操作、递归转移等。
3. 分析循环的实际总次数：嵌套循环相乘，两个指针要看是否单调移动，减半则考虑对数。
4. 把顺序步骤相加、保留最高阶项，并选择最坏或题目要求的情况。
5. 统计额外数据结构和递归栈：哈希表、数组、队列、访问数组、结果集都要考虑。
6. 检查隐藏复制：切片、字符串拼接、排序副本、递归参数复制。
7. 用约束反推目标复杂度：输入规模越大，允许的复杂度通常越低。

## 9. 面试或题解中的标准写法

```text
时间复杂度：O(...)
空间复杂度：O(...)
其中空间复杂度按额外空间计算，输入数组和返回结果是否计入需按题目约定说明。
```

例如二分查找的迭代实现：

```text
每次将搜索区间缩小为原来的一半，因此时间复杂度为 O(log n)。
只使用 left、right、mid 等固定数量的变量，因此额外空间复杂度为 O(1)。
```
